# 移植说明

源：`misc/minelzu-1.0.0+1.21.11.jar`（Fabric 1.21.11，包名 `top.welancraft.minelzu`，
6 个方块类 1 个客户端类 + 全套 assets）。目标：Minecraft 26.3 / NeoForge 26.3.0.95，
Kotlin + Kotlin for Forge。

## 入口与注册

| 1.21.11 Fabric | 26.3 NeoForge + Kotlin |
| --- | --- |
| `ModInitializer.onInitialize()` | `@Mod(MineLZU.MODID) class MineLZU(modEventBus, modContainer)` 的 `init` |
| `Registry.register(BuiltInRegistries.BLOCK, id, block)` | `DeferredRegister.Blocks.registerBlock(name, factory)` |
| `new BlockItem(block, props.useBlockDescriptionPrefix())` | `DeferredRegister.Items.registerSimpleBlockItem(holder)`（内部已调用 `setId` 与 `useBlockDescriptionPrefix`） |
| `Registry.register(BuiltInRegistries.CREATIVE_MODE_TAB, ...)` | `DeferredRegister.create(Registries.CREATIVE_MODE_TAB, MODID)` |
| `FabricItemGroup.builder()` | `CreativeModeTab.builder()` |
| `ResourceLocation` / `Identifier.fromNamespaceAndPath` | 26.3 中 `ResourceLocation` 已改名为 `net.minecraft.resources.Identifier`，工厂方法同名 |
| `LinkedHashMap<String, Block>` 内容表 | `ModBlocks` 内部的 `registered` 表，`ModBlocks.all` 暴露只读视图 |

原版 `ModContent.register()` 里的 `setId(ResourceKey.create(Registries.BLOCK, id))`
由 `DeferredRegister.Blocks.registerBlock` 自动完成，因此新代码里不再出现 `setId`。

## 方块 API 映射

| 1.21.11（Yarn/官方名） | 26.3 |
| --- | --- |
| `StairsBlock` | `net.minecraft.world.level.block.StairBlock`（单数） |
| `VoxelShape getOutlineShape(...)` | `protected VoxelShape getShape(state, level, pos, context)` |
| `VoxelShape getCameraCollisionShape(...)` | `protected VoxelShape getVisualShape(...)` |
| `int getOpacity(...)`（原实现返回 12） | `protected int getLightDampening(state)`（返回 12） |
| `boolean isTransparent(...)` / `skipRendering` | `protected boolean skipRendering(state, neighborState, direction)`（返回 false） |
| `Block.box(...)` | `Shapes.box(minX, minY, minZ, maxX, maxY, maxZ)` |
| `getRaycastShape`（原实现返回空） | `getInteractionShape`，原版默认已是空，故不再覆写 |
| `appendProperties` | `createBlockStateDefinition(builder.add(FACING))` |
| `getPlacementState` | `public BlockState getStateForPlacement(BlockPlaceContext)`（必须为 public） |
| `BlockStateProperties.HORIZONTAL_FACING` | 同名，包路径为 `net.minecraft.world.level.block.state.properties` |

`HorizontalStairsBlock` 仍然保留为 `StairBlock` 的空子类，与原版一致。

## 渲染层的处理（与 1.21.11 的差异）

1.21.11 版本用 `BlockRenderLayerMap` 指定：

* CUTOUT：`ow_02`、`a2_openwork`、`support_bar`、`a2_wall_lamp`、`lamp_post`
* TRANSLUCENT：`tg_blue`

26.3 已移除按方块注册渲染层的 API（没有 `ItemBlockRenderTypes` / `setRenderLayer`），
渲染层由区块编译时根据 sprite 的透明度自动决定
（`ChunkSectionLayer.byTransparency`）。对现有纹理做了 alpha 审计：

| 纹理 | alpha 情况 | 自动得到的层 |
| --- | --- | --- |
| `tg_blue.png` | 全部 256 像素 alpha=150（半透明） | TRANSLUCENT |
| `a2_openwork`、`co_01`、`lamp_post`、`a2_wall_lamp`、`support_bar`、`ow_02` | 存在 alpha=0 像素 | CUTOUT |
| 各 `bricks_*`、`ow_02_cube`、`ow_01` | 完全不透明 | SOLID |

结论：不需要任何渲染层代码，`MineLzuClient`（Fabric 客户端入口）在移植中被删除。
注意 `co_01` 在原版没有被显式登记为 CUTOUT，但纹理本身有透明像素，行为等价。

## 资源 JSON

* `blockstates`、`models/block`、`models/item`、`items` 原先为手写，现已全部由
  datagen 生成，详见[资源数据生成](资源数据生成.md)；
* `data/minecraft/tags/block/walls.json` 也改为 datagen；
* `lang/en_us.json`、`lang/zh_cn.json`、全部纹理仍为手写资源；
* 1.21.11 版 `ow_02` 的 blockstate 中 `facing=east` 与 `facing=west` 都是 `y=90`
  （原版贴图方向如此），移植时按原样保留，datagen 里对应的就是
  `ow02Facing` 那张表。

## 已确认的假设

1. 原始 jar 用 Yarn 中间名编译，反编译后 `MapColor.field_16023`、
   `SoundType.field_11544` 之类的常量无法在离线环境还原真实字段。
   按语义取值：石材方块用 `MapColor.STONE` + `SoundType.STONE`，
   `tg_blue` 用 `MapColor.COLOR_LIGHT_BLUE` + `SoundType.GLASS`。
   如需与原版完全一致，改 `ModBlocks.stone(...)` / `ModBlocks.glass(...)` 即可。
2. 原 `NoCollisionFullOutlineBlock` 还覆写了一个三参数形状方法（原版默认返回空），
   行为等价于默认实现，因此没有保留。
3. `minelzu.mixins.json` 与 `neoforge.mods.toml` 里的 `[[mixins]]` 段是模板残留
   （包名指向另一个模组且 `mixins` 为空），已删除。
4. `assets/minecraft/optifine/emissive.properties` 只存在于原始 jar 中，
   26.3 无对应机制，未移植。

## 跨加载器（Architectury）改造

第一版是单平台（NeoForge + Kotlin for Forge）。之后按 Architectury 的多平台结构重构为
`common` / `fabric` / `neoforge` 三模块，两个加载器共用同一份逻辑与资源：

| 第一版（单平台） | 现在（Architectury） |
| --- | --- |
| `@Mod class MineLZU(modEventBus, modContainer)` | `object MineLZU` 的 `init()`；平台入口是 `MineLZUNeoForge` / `MineLZUFabric` |
| `net.neoforged.neoforge.registries.DeferredRegister` | `dev.architectury.registry.registries.DeferredRegister` + `RegistrySupplier` |
| `DeferredRegister.Blocks.registerBlock(...)` | `DeferredRegister.create(MODID, Registries.BLOCK)` 后 `register(name) { factory(properties) }` |
| `DeferredRegister.Items.registerSimpleBlockItem(...)` | `register(name) { BlockItem(...) }`，`setId` 与 `useBlockDescriptionPrefix` 显式调用 |
| 创意标签页用 NeoForge `CreativeModeTab.builder()` | `CreativeModeTab.Builder(CreativeModeTab.Row.TOP, 0)`（vanilla 构造器；无参 `builder()` 是 NeoForge 的补丁） |
| datagen 挂 `GatherDataEvent.Client` 于主类 | provider 留在 `common`，事件监听器移到 `neoforge/.../ModDatagen.kt` |
| `NeoForge` 的 `ModelProvider` 子类 | 直接实现 vanilla `DataProvider`，用 access widener 放宽 `BlockModelGenerators` 的私有成员 |

平台细节与构建脚本的取舍见[多平台架构](多平台架构.md)与[开发与构建](开发与构建.md)。
方块、注册名、资源名、`lang` 键与第一版完全一致，两个加载器的 jar 都能独立安装。
