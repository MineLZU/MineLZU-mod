## 常用命令

```powershell
.\gradlew.bat :common:compileKotlin      # 只编译公共代码
.\gradlew.bat :neoforge:build            # NeoForge 平台 jar
.\gradlew.bat :fabric:build              # Fabric 平台 jar
.\gradlew.bat build                      # 两个平台都构建
.\gradlew.bat :neoforge:runData          # 重新生成 common/src/generated/resources
.\gradlew.bat :neoforge:runClient        # NeoForge 客户端
.\gradlew.bat :neoforge:runServer        # NeoForge 服务端（--nogui）
.\gradlew.bat :fabric:runClient          # Fabric 客户端
```

`build` 之后，可直接安装的产物是 `-1.0.0.jar`（不再是 `-dev.jar`）；
`-dev.jar` 与 `-sources.jar` 只用于开发。

## datagen

```groovy
# neoforge/build.gradle
loom {
    runs {
        data {
            clientData()
            devLaunchMainClass = 'net.neoforged.fml.startup.DataClient'
            programArgs '--mod', rootProject.mod_id, '--all'
            programArgs '--output', rootProject.file('common/src/generated/resources').absolutePath
            programArgs '--existing', rootProject.file('common/src/main/resources').absolutePath
        }
    }
}
```

一次 `:neoforge:runData` 同时产出客户端资源（blockstates / models / items）与服务端数据
（方块标签），输出到 `common/src/generated/resources`，该目录被 `common` 的
`sourceSets.main.resources.srcDir` 一起打包（`.cache` 子目录被排除）。

`GatherDataEvent.Client` 的监听器在 `neoforge/src/main/kotlin/.../neoforge/ModDatagen.kt`，
两个 provider 本身在 `common` 里，且只依赖 vanilla 的 `DataProvider` / `PackOutput` API，
因此两个加载器都能编译通过。

Fabric 侧没有单独的 datagen run：`common` 的数据只要生成一次即可，两端共用同一份产物。

## 构建脚本要点

* **不要从根项目的 `subprojects { }` 里 apply loom**：子项目还没评估时 apply 会在
  `Configuration.extendsFrom(Provider[])` 上抛 `NoSuchMethodError`。loom 必须在每个模块自己的
  `plugins { }` 里声明。
* `minecraft "net.minecraft:minecraft:26.3"` 依赖要放在
  `plugins.withId('dev.architectury.loom-no-remap') { }` 里，否则 loom 未应用时会报
  `Could not find method minecraft()`。
* `gradle.properties` 里的 `fabric.loom.disableObfuscation=true` 是必需的：
  loom 的 `LoomGradleExtensionImpl` 用 `pluginManager.hasPlugin('dev.architectury.loom-no-remap')`
  判断是否免混淆，实测在本仓库的模块脚本里不生效，用属性开关才可靠。
* `loom.platform` 放在各模块自己的 `gradle.properties`（`neoforge` / `fabric`），
  否则 `neoForge` / `fabric` 依赖配置会报 `Could not find method neoForge()`。
* `kotlin.stdlib.default.dependency=false`，标准库以 `compileOnly` 引入：
  运行时由 fabric-language-kotlin / Kotlin for Forge 提供，避免打进 jar。
* `shadowBundle(project(path: ':common')) { transitive = false }`：只把 `common` 的类和资源
  合进平台 jar，Architectury API、Fabric Loader、Kotlin 标准库等仍是外部 mod 依赖。
* `org.gradle.configuration-cache=false`：loom 与 Kotlin 插件在该组合下会因配置缓存报错。

## 常见错误

| 现象 | 原因与处理 |
| --- | --- |
| `Configuration 'mappings' has no dependencies` | Gradle 版本过低或 `fabric.loom.disableObfuscation` 未生效；升级到 9.7.1 并加上该属性 |
| `Not bootstrapped (called from registry ...)` | loom 默认用 Dev Launch Injector 启动，`Bootstrap` 被两个类加载器各定义一份；给 run 设置 `devLaunchMainClass = 'net.neoforged.fml.startup.DataClient'` 等真实主类 |
| `NoClassDefFoundError: io/github/minelzu/minelzu_mod/MineLZU` | `loom { mods { } }` 里出现了多余的分组，FML 看到同 modid 的两个 mod file；只保留 `main` 组并把 `common` 挂进去 |
| `Registry is already frozen` | datagen 阶段注册表已冻结，方块必须在 supplier 里懒创建 |
| `Missing classTweaker file minelzu.accesswidener` | Fabric dev 从 mod 根目录找 AW；`fabric` 的 `processResources` 需要把 `common` 的 AW 复制到 jar 根 |
| `Unsupported class file major version 71` | architectury-plugin 的 dev transformer 用旧 ASM 读 lwjgl 的 Java 27 类；本仓库已移除该插件 |

## 代码约定

* 只用 Kotlin 与 Kotlin 标准库，Java 平台 API 仅在必须时使用（如 `java.util.function.Supplier` 做 SAM 消歧）。
* 代码内不写注释；用法、约定、决策写在本目录文档里。
* 资源 JSON（blockstates / models / items / data tags）一律由 datagen 产出，不手写。
  `lang` 文件是例外，仍然手写维护。
